DeepONets required for the figures of
"The Error of Deep Operator Networks Is the Sum of Its Parts:
 Branch-Trunk and Mode Error Decompositions"  (arXiv:2602.21910v1)

ALL figures: main body (1-9) and appendix (10-12).

Nets are identified by their net-directory name, which is exactly the name
built by src/execute_don.py (line 95ff) from its command-line arguments.
Every net below was created with

  cd src && python execute_don.py  Nep vtag d w llw doplot batch_name lrstag init_lr \
                                   decay num_data whichT doSigma uendtag sisc exp doadam doStacked \
                                   adaptiveLR momentum

(execute_don.py does `from don_code import *`, so it is run from inside src/, the way
src/run.py invokes it.  All 20 arguments are mandatory; `adaptiveLR` (argv[19]) and
`momentum` (argv[20]) used to be hardcoded to False/True inside the script and are now
passed in.  Every net in this file was made with adaptiveLR=0 and momentum=1, except the
AdaGrad net of Fig. 11, which uses momentum=0 - so the trailing pair is "0 1" everywhere
but there.)

----------------------------------------------------------------------------------------------------
GETTING THE NETS: they do NOT have to be retrained.  All of them are already on HuggingFace
(jo-chen/deeponet-data, 107 net directories) and are pulled with

  python hf_pull.py jo-chen/deeponet-data --subset nets datasets sb_data

Checked against that repo (2026-08-07): of the 97 directories named in this file, 96 are
present verbatim.  The remaining one,

  whichT0_doStackedFalse_doSigma1_sisc1.0_aT0.0_aB0.0_exp0.0_Nep4000_d5_w335_llw50_batkdvnx401_dt0.0001_nc5_m5000_1999_numd1000_lrSGD32_v0

is on HuggingFace too but with the suffix "_unnecessary?" appended to the directory name,
so the analysis scripts do not see it.  That is deliberate - see the Fig. 4 notes.
----------------------------------------------------------------------------------------------------

Seeds: the seed is `vtag` (execute_don.py: key = jax.random.PRNGKey(vtag)) and it
appears as the trailing "_v<vtag>" in the directory name.  Every net BELOW is the vtag=0
one, which is what the published figures use.

  PLANNED: a 10-seed sweep, vtag = 0..9, of every net in this file EXCEPT the four
  Figure 6 (synthv) nets - 89 configs x 10 = 890 training runs on the MPI-IS cluster.
  vtag only reseeds jax.random.PRNGKey, i.e. the network INITIALISATION; load_dataset
  takes a deterministic 90/10 prefix split with no shuffling, so all seeds see identical
  data.  That is intended.
  The Fig. 9 post-processing scripts now take the seed as a trailing argument (see the
  Fig. 9 block).  The plotting/analysis scripts do NOT yet - they all still hardcode
  "_v0" - so they will have to be adapted before any seed-averaged figure can be made.

Learning-rate tags (src/run.py, lrs()):  lrAdam40 / lrSGD40 -> init_lr 2e-3, decay 0.95
                                         lrAdam32 / lrSGD32 -> init_lr 1e-4, decay 0.95
Optimizer, from the lr prefix in the name (execute_don.py, doadam/momentum):
  lrSGD..  = plain GD      (doadam 0)
  lrAdam.. = Adam          (doadam 1, momentum True)
  lrAda..  = AdaGrad       (doadam 1, momentum False -> optax.adam(b1=0.0)); only Fig. 11.
Trunk id whichT (execute_don.py header):  -1 Learned, 0 SVD, 1 Leg., 2 Cheb., 7 Cos.
Datasets (src/don_code.py dic()), loaded from data/datasets/:
  bid 0 -> advdiffnx201_dt0.0005_nc20_m1000, uendtag 1000   (AD,  tau=0.5)
  bid 3 -> kdvnx401_dt0.0001_nc5_m5000,      uendtag 1999   (KdV, tau=0.2)
  bid 4 -> kdvnx401_dt0.0001_nc5_m5000,      uendtag 5999   (KdV, tau=0.6)
  bid 6 -> burgers_dt0.0001_nc10_m3800,      uendtag 100    (Burgers, tau=0.1 in Table 4)
All four are on HuggingFace under data/datasets/.

An epoch count in a directory name is only the length of the training RUN.  Several
analysis scripts truncate what they read (e.g. analyze_mode_losses_rotate.py fixes
num_epochs = 80 log rows = 4000 epochs), and the lr schedule is epoch-based, so a longer
run is identical to a shorter one over the shared prefix.  This is why several names below
say Nep10000 while Table 3 of the paper lists 4000 epochs.

Figure -> script mapping is produce_all_figures.py.

NOTE 1: the script's direcs list for whichones=4 contains SIX entries - both an
        exp0.0/Nep10000 and an exp0.0/Nep4000 net.  The figure has exactly 5 columns, so
        only one of them may exist in data/nets.  On HuggingFace the Nep4000 one is
        parked under the name '..._lrSGD32_v0_unnecessary?' precisely so the scripts
        skip it, which means the e=0.0 column is the Nep10000 net.  Do not rename that
        directory back.
NOTE 2: the paper (var1, App. A) states alpha_1 = 1e-4 * sigma_1^(-2e) for this figure.
        In execute_don.py that rescaling is `adaptive_init_lr`, the mandatory 19th
        argument (it used to be hardcoded to False).  It does the arithmetic for you:
        init_lr *= ss_train[0]**(-2*exponent), with ss_train[0] = sigma_1 of utrain
        (execute_don.py, ~line 184).  So you do NOT need to know sigma_1 to train these.

        The catch is only the NAME: for |e| > 1e-12, adaptiveLR=1 writes '_expA<e>'
        instead of '_exp<e>' (execute_don.py, ~line 96).  That distinction is deliberate
        and stays - a scaled and an unscaled run must not collide on one directory - but
        it means an adaptiveLR=1 net is NOT found by analyze_mode_losses_rotate.py, which
        looks for '_exp<e>'.  Hence the published names cannot have come from adaptiveLR=1.
        For e=0.0 the question is moot: sigma_1^0 = 1 and the name branch needs |e|>0.

        DECIDED: use adaptiveLR=1 with init_lr = 1e-4 (route (a)), i.e. let the code do
        the sigma_1 arithmetic, then rename the four resulting directories.  That is what
        the command line above shows.  The full recipe for the four e != 0 nets:

          1. train them:
               cd src
               for e in -1.0 -0.5 0.5 1.0; do
                 python execute_don.py 4000 0 5 335 50 0 kdvnx401_dt0.0001_nc5_m5000 \
                        32 1e-4 0.95 1000 0 1 1999 1.0 $e 0 0 1 1
               done
          2. rename '_expA<e>' -> '_exp<e>' so the analysis script finds them:
               cd ../data/nets
               for d in *_expA*; do mv "$d" "${d/_expA/_exp}"; done
             (only these four directories ever carry '_expA', so the glob is safe as long
              as no other adaptiveLR=1 run is sitting in data/nets at the time.)

        The alternative - adaptiveLR=0 with the scaled value passed as init_lr by hand -
        was rejected as more error-prone.  For reference, that value would have been
          e=-1.0 -> 1e-4 * sigma_1^( 2.0)      e= 0.5 -> 1e-4 * sigma_1^(-1.0)
          e=-0.5 -> 1e-4 * sigma_1^( 1.0)      e= 1.0 -> 1e-4 * sigma_1^(-2.0)
        with sigma_1 = largest singular value of utrain for KdV tau=0.2, obtainable with
          cd src && python -c "from don_code import *; \
            *_, utrain, utest = load_dataset('kdvnx401_dt0.0001_nc5_m5000','1999',1000); \
            print(np.linalg.svd(utrain, compute_uv=False)[0])"

        CONFIRMED BY THE AUTHOR: var1 was indeed applied for fig. 4, i.e. the published
        nets really do use alpha_1 = 1e-4 * sigma_1^(-2e) and not a flat 1e-4.  This is
        not recoverable from the directories themselves - either route ends up named
        '_exp<e>_..._lrSGD32' - so it is recorded here.
